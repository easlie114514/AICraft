# AICraft 构建与打包指南

> 本文档面向 AI Agent 或其他开发者，在一台新电脑上完成从源码到发布 ZIP 的全流程构建。

## 3. 构建流程

### 推荐方式：一键构建

```bash
cd /d/AICraft
python build_exe.py
```

此脚本按顺序执行 4 步：

#### Step 1：构建前端

```
cd frontend && npm install && npm run build
```

- 由 tsc 做 TypeScript 类型检查，然后 vite 打包
- 产物：`frontend/dist/`（含 index.html, assets/）
- 如果 `frontend/node_modules/` 已存在，跳过 npm install

#### Step 2：PyInstaller 打包（OneDir 模式）

```
pyinstaller --clean "aicraft.spec"
```

- 入口：`run.py`
- 模式：**onedir**（非 onefile），输出到 `dist/AICraft/`
- 产物结构：
  ```
  dist/
  ├── AICraft.exe           # 顶层 bootloader wrapper（不独立运行）
  └── AICraft/              # 真正的完整包
      ├── AICraft.exe        # 可执行文件（22MB 左右）
      └── _internal/         # Python 运行时 + 数据文件 + DLL
  ```

#### Step 3：创建发布目录

```python
# 完整复制 dist/AICraft/ → release/AICraft/
shutil.copytree(src_onedir, RELEASE_DIR)

# 预创建运行时目录
config/profiles, models, roles, skills, mcp, rag,
memory/conversations, memory/project-notes, chroma_db, workspace

# 复制出厂默认配置
config/defaults/*.json → release/AICraft/config/defaults/

# 复制 README
RELEASE_README.md → release/AICraft/README.md
```

- **注意**：必须复制整个 `dist/AICraft/` 目录（含 `_internal/`），不能只复制顶层 `dist/AICraft.exe`

#### Step 4：创建 ZIP

```
PowerShell Compress-Archive release/AICraft/* → release/AICraft.zip
```

- ZIP 大小约 185 MB（含完整 Python 运行时）
- 用户解压后双击 `AICraft.exe` 即可运行

## 4. Spec 文件关键配置

文件：`aicraft.spec`

### datas（打入 `_internal/data/` 的出厂只读数据）

| 源路径 | 目标路径 | 说明 |
|---|---|---|
| `skills/` | `data/skills` | Skill 定义 |
| `roles/` | `data/roles` | 角色定义 |
| `rag/` | `data/rag` | RAG 文档 |
| `models/onnx/` | `data/models/onnx` | ONNX embedding 模型 |
| `frontend/dist/` | `data/frontend/dist` | 前端构建产物 |
| `config/defaults/` | `data/config/defaults` | 出厂默认配置 |
| `src/mcp_servers/code_executor.py` | `data/src/mcp_servers` | MCP 服务器脚本 |

### excludes（排除的巨型包，减小体积）

- `torch`, `transformers`, `sentence_transformers` — chromadb 在 ONNX 模式下不需要
- `tkinter`, `matplotlib`, `pandas`, `numpy.tests`, `scipy`, `PIL`, `cv2`

### hiddenimports（强制打包，防止静态分析遗漏）

- chromadb 全套：`chromadb`, `chromadb.api.rust`, `chromadb.api.segment`, `chromadb.telemetry.product.posthog`, `chromadb.db.impl.sqlite`
- backend 全部路由：`backend`, `backend.main`, `backend.chat_ws`, `backend.routers.*` — uvicorn 使用字符串引用，PyInstaller 静态分析无法发现
- src 全部模块：`src.core.*`, `src.utils.*`, `src.mcp_servers.*`
- 运行时依赖：`onnxruntime`, `tokenizers`, `tqdm`, `httpx`, `httpcore`, `anthropic`, `mcp`, `pywebview`, `pyperclip`

### icon

```python
icon=str(ROOT / 'logo_item.ico'),
```

- 图标源文件 `logo_item.png` (2048×2048)，压缩为多尺寸 `.ico` (53KB)
- 转换命令：Python Pillow `img.save('logo_item.ico', format='ICO', sizes=[(256,256),(128,128),(64,64),(48,48),(32,32),(16,16)])`

### console=False

无控制台窗口，纯 GUI 应用。

## 5. 路径架构（打包后）

代码在 `src/utils/config.py` 中通过 `_FROZEN` 区分两种模式：

| 变量 | 开发模式 | 打包模式 |
|---|---|---|
| `APP_DIR` | 项目根目录 | `sys._MEIPASS/data/` (exe 内部只读) |
| `USER_DIR` | 同 `APP_DIR` | `%APPDATA%/AICraft/` |
| `BASE_DIR` | 同 `APP_DIR` | 同 `APP_DIR` |

### 只读数据（打包后存于 `_internal/data/`）

- `SKILLS_DIR`, `ROLES_DIR`, `RAG_DIR`, `DEFAULTS_DIR`, `FRONTEND_DIST`, `ONNX_MODEL_DIR`

### 用户可写数据（打包后存于 `%APPDATA%/AICraft/`）

- `CONFIG_DIR`, `PROFILES_DIR`, `MODELS_DIR`, `MEMORY_DIR`, `CHROMA_DIR`, `WORKSPACE_DIR`

### 出厂初始化

`ensure_user_dirs()` 在首次启动时自动创建所有用户目录，并从 defaults 复制初始配置。使用 `.version` 文件标记是否首次启动。

**重要**：发给其他人使用时，对方电脑上 `%APPDATA%/AICraft/` 为空，会自动获得出厂预制状态。如果你本地测试过，`%APPDATA%/AICraft/` 会有旧数据残留。

## 6. MCP 子进程机制（易错点）

打包后的 exe 通过 `--mcp-server <name>` 自举启动内置 MCP 服务器：

1. `mcp_client.py` 的 `_normalize_stdio_params()` 检测到 frozen 模式，将 `python src/mcp_servers/code_executor.py` 转换为 `AICraft.exe --mcp-server code_executor`
2. `run.py` 的 `if __name__ == "__main__"` 块必须先检查 `--mcp-server` 和 `--run-script` 参数，**在 `main()` 之前拦截**
3. 如果没拦截，子进程会启动完整的 webview 窗口（导致多窗口闪现）

```python
# run.py 中的关键代码
if __name__ == "__main__":
    if len(sys.argv) >= 2:
        if sys.argv[1] == "--mcp-server" and len(sys.argv) >= 3:
            # 执行 MCP stdio server，不启动 webview
            ...
            sys.exit(0)
        if sys.argv[1] == "--run-script" and len(sys.argv) >= 3:
            # 执行临时脚本，不启动 webview
            ...
            sys.exit(0)
    main()
```

## 7. 常见问题

### 7.1 `npm run build` 失败
- 确认 `frontend/node_modules/` 存在，否则先 `cd frontend && npm install`
- TypeScript 编译报错：检查 `frontend/tsconfig.json` 和 `.ts/.tsx` 文件语法

### 7.2 PyInstaller 报 COLLECT 目录非空
- 先清理：`rm -rf dist build` 再重试

### 7.3 打包后运行提示找不到 `python313.dll`
- 确认运行的是 `dist/AICraft/AICraft.exe`（不是顶层 `dist/AICraft.exe`）
- release ZIP 必须包含完整的 `_internal/` 目录

### 7.4 打包后出现多个窗口
- 确认 `run.py` 已正确处理 `--mcp-server` 和 `--run-script` 参数拦截

### 7.5 MCP 前端报 UTF-8 解码错误
- 同上，子进程走纯 stdio 协议，不能有 FastAPI/uvicorn 日志输出污染 stdout

### 7.6 打包后看到旧模型配置/聊天记录
- 用户数据在 `%APPDATA%/AICraft/`，这是本地残留
- 新用户电脑上不会有此问题
- 开发测试可手动删除：`rmdir /s "%APPDATA%\AICraft"`

### 7.7 图标还是 Python 默认图标
- 确认 `aicraft.spec` 中有 `icon=str(ROOT / 'logo_item.ico')`
- 确认 `logo_item.ico` 文件存在于项目根目录

## 8. 构建产物清单

| 文件/目录 | 大小 | 用途 |
|---|---|---|
| `dist/AICraft/AICraft.exe` | ~22 MB | 可独立运行的应用（依赖同级 `_internal/`） |
| `dist/AICraft/_internal/` | ~300 MB | Python 运行时 + 依赖库 + 数据 |
| `release/AICraft/` | ~320 MB | 发布版完整目录（exe + 运行时 + 预置空目录 + README） |
| `release/AICraft.zip` | ~185 MB | 发布压缩包 |

## 9. 升级 check list

当源码有重大变更时，检查以下项：

- [ ] 新增 Python 包：加入 spec 的 `hiddenimports`
- [ ] 新增超大依赖（如 torch）：加入 spec 的 `excludes`
- [ ] 新增前端页面路由：确认 vite 打包正常
- [ ] 新增 MCP 服务器：确认 `_normalize_stdio_params` 能正确映射
- [ ] 新增出厂数据目录：加入 spec 的 `datas`
- [ ] 更换图标：更新 `logo_item.ico` 和 spec 中 `icon=` 引用
- [ ] 修改 `run.py` 入口逻辑：确认 `--mcp-server` / `--run-script` 拦截在最前面
- [ ] 发送前：在新的/干净的电脑上解压 ZIP 验证启动
