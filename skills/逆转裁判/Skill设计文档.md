# 逆转裁判 Skill - 完整设计文档

## 一、核心理念
**推广 AICraft**：通过这个游戏展示 AICraft 的 Skill 系统 + 文件管理能力

## 二、游戏流程

### 2.1 触发条件
玩家输入类似"玩一局逆转"、"开始逆转裁判"等关键词，Skill 开始工作

### 2.2 初始化流程
1. 检查或创建"逆转裁判"目录
2. 在该目录下新建本次故事标题目录（如"雨夜别墅杀人事件"）
3. 生成完整剧本（案件真相、角色、证物、证言）
4. 创建备份目录 `_backup/`
5. 创建玩家操作目录 `workspace/`
6. 将证物、场景、证言保存到 `_backup/`，并记录 hash 值
7. 创建角色文件（固定角色 + 随机角色）
8. 初始化游戏状态 `game_state.json`

### 2.3 调查阶段
1. 介绍故事背景
2. 切换到"Game-绫里真宵"角色
3. 真宵指引玩家：
   - 可以切换委托人了解案件情况
   - 可以查看 `workspace/` 中的证物和场景
   - 证物根据难度分阶段释放
4. 玩家获取所有证物和信息后，输入"我准备好开庭了"
5. 确认进入庭审阶段

### 2.4 庭审阶段
1. 审判长宣布开庭
2. 检察官陈述案件
3. 证人作证（给出有缺陷的证言）
4. 玩家可以：
   - 和真宵讨论（默认对话对象）
   - 对审判长说话（"审判长，我申请..."）
   - 对检察官说话（"御剑，你错了！"）
   - 对证人说话（"证人，你说..."）
   - 举证（选择证物，指出矛盾）
5. 系统检查证物合法性（hash 对比 + stage 检查）
6. 审判长判定结果
7. 循环直到所有证言结束
8. 最终指证环节

### 2.5 多庭审理（难度系统）
- **简单（1庭）**：所有证物在第1庭前全部可用
- **普通（2庭）**：
  - 第1庭：基础证物 + 第1个证人
  - 第2庭：新证物 + 第2个证人
- **困难（3庭）**：
  - 第1庭：基础证物 + 第1个证人
  - 第2庭：新证物 + 关键人公开（新证人或新证据）+ 第2个证人
  - 第3庭：最终证物 + 最终证言

### 2.6 结局判定
- **True End**：正确指认真凶 + 关键证物链完整
- **Bad End**：
  - 指认错误的人
  - 伪造证物被审判长轰出去
  - 未能在关键节点指证

## 三、证物系统

### 3.1 目录结构
```
逆转裁判/
└── 雨夜别墅杀人事件/
    ├── _backup/              # 备份目录（Skill 管理）
    │   ├── evidence/         # 原始证物
    │   ├── scenes/           # 原始场景
    │   └── testimony/        # 原始证言
    ├── workspace/            # 玩家操作目录
    │   ├── evidence/         # 玩家可操作的证物
    │   └── scenes/           # 玩家可操作的场景
    ├── characters/           # 角色定义
    │   ├── 绫里真宵.md
    │   ├── 审判长.md
    │   ├── 御剑怜侍.md
    │   ├── 证人_XXX.md
    │   └── 委托人_XXX.md
    ├── case_info.json        # 案件信息
    └── game_state.json       # 游戏状态
```

### 3.2 证物备份与伪造检测
**游戏开始前**：
1. 生成所有证物，保存到 `_backup/evidence/`
2. 计算每个证物的 hash 值
3. 记录到 `case_info.json`：
```json
{
  "case_name": "雨夜别墅杀人事件",
  "truth": "A在XX时间用XX物品杀害了B...",
  "difficulty": 2,
  "total_courts": 2,
  "evidence_list": [
    {
      "name": "带血的刀.txt",
      "hash": "abc123...",
      "court_stage": 1,
      "backup_path": "_backup/evidence/带血的刀.txt"
    }
  ],
  "witnesses": ["证人A", "证人B"],
  "defendant": "委托人XXX",
  "culprit": "证人A"
}
```

**调查阶段**：
- 根据 `game_state.current_court`，将对应证物从 `_backup/` 复制到 `workspace/evidence/`

**庭审阶段 - 伪造检测**：
- 玩家举证时，系统检查：
  1. 证物是否存在于 `case_info.json.evidence_list` 中？
  2. 证物内容是否与备份一致？（对比 hash）
  3. 证物的 `court_stage` 是否 <= `game_state.current_court`？
- 如果任一检查失败：
  ```
  【审判长】等一下！本庭注意到这个证物有问题...
  【审判长】（仔细查看）这个证物的内容与实际不符！
  【审判长】你被指控伪造证据，本庭现在休庭！咚！
  【系统】Bad End - 伪造证据
  ```

## 四、角色系统

### 4.1 固定角色
- **Game-绫里真宵**：玩家扮演，搭档，称呼玩家为成步堂
- **Game-审判长**：主持庭审，判定举证结果，检测伪造证物
- **Game-御剑怜侍**：检察官，指控被告，反驳玩家

### 4.2 随机角色
- **证人**：随机生成性格（符合逆转裁判浮夸风格）
- **委托人**：随机生成性格
- **关键人**（困难模式）：第2庭时公开

### 4.3 对话规则
- 玩家始终扮演"绫里真宵"
- 其他角色发言时，系统注入该角色的性格描述
- 消息格式：`【角色名】发言内容`
- 玩家发言需要指定对象：
  - `"审判长，我申请..."` → 对审判长说话
  - 未指定角色 → 默认对真宵说话

## 五、庭审交互逻辑

### 5.1 证言阶段
1. 证人上台作证（给出有缺陷的证言）
2. 玩家可以：
   - 询问证言（对证言的某句话追问）
   - 举证（选择证物，指出矛盾）
3. 如果举证正确：
   - 证人慌乱，暴露更多信息
   - 进入下一段证言
4. 如果举证错误：
   - 审判长警告
   - 如果是伪造证物，直接 Bad End
5. 循环直到所有证言结束

### 5.2 最终指证
1. 所有证言结束后，玩家需要选择指认对象
2. 指认正确 → True End
3. 指认错误 → Bad End

### 5.3 多庭审理
1. 第1庭结束（未指认或指认失败）→ 休庭
2. 进入调查阶段（获取新证物）
3. 第2庭开始（新证人/关键人）
4. 循环直到最终庭

## 六、游戏状态管理

### 6.1 game_state.json
```json
{
  "current_stage": "investigation",  // investigation / trial / ending
  "current_court": 1,                // 当前第几庭
  "collected_evidence": [],          // 已获取的证物
  "questioned_testimony": [],        // 已询问的证言
  "culprit_accused": null,           // 指认的凶手
  "game_result": null                // true_end / bad_end_forgery / bad_end_wrong / bad_end_no_accuse
}
```

### 6.2 状态流转
- 游戏开始 → `current_stage = investigation`
- 玩家准备开庭 → `current_stage = trial`
- 第1庭结束 → `current_court = 2`, `current_stage = investigation`
- 玩家指认凶手 → `current_stage = ending`, `culprit_accused = XXX`
- 判定结局 → `game_result = XXX`

## 七、推广 AICraft 的卖点

1. **Skill 系统**：展示 AICraft 的 Skill 加载和执行能力
2. **文件管理**：展示 AICraft 的文件读写、目录管理能力
3. **角色切换**：展示 AICraft 的角色扮演和上下文切换能力
4. **证物伪造检测**：展示 AICraft 的文件 hash 计算和对比能力
5. **多庭审理**：展示 AICraft 的游戏状态管理能力

## 八、实现优先级

### P0（核心功能）
1. 剧本生成逻辑（案件真相、角色、证物、证言）
2. 证物备份和复制机制
3. 伪造检测机制
4. 庭审交互逻辑（角色切换、举证判定）
5. 结局判定

### P1（增强功能）
1. 多庭审理流程
2. 关键人系统（困难模式）
3. 证物分阶段释放
4. 对话记录

### P2（可选功能）
1. 存档/读档
2. 提示系统
3. 证物图片（xlsx 表格展示）
