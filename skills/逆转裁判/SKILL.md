# 逆转裁判 Skill

## 基本信息
- **名称**：逆转裁判
- **用途**：文字推理游戏，推广 AICraft 的 Skill 系统和文件管理能力
- **触发条件**：玩家输入"玩一局逆转"、"开始逆转裁判"、"逆转裁判"等关键词

## 🔴 核心铁律：剧本必须在游戏开始前100%确定

**绝对不能出现**：
- 玩家聊天过程中动态生成剧情
- 大模型即兴编造关键信息
- 剧情因为玩家闲聊而走偏，导致无法到达结局

**必须保证**：
- 玩家触发游戏后，Skill **先生成完整的剧本**（JSON 格式，包含所有关键信息）
- 所有关键信息预先确定：凶手、动机、证物链、证言缺陷、结局条件
- 游戏过程中，大模型只是"读剧本"与玩家交互
- 非关键对话可以灵活，但关键信息（证言、证物、凶手）必须100%按剧本
- **证物内容禁止直接暴露真相**：证物文件只能包含客观描述和线索（如"刀上有指纹"、"地面有泥脚印"），严禁在证物中直接写明凶手身份、作案动机或结论性推理。真相只在 `案件信息.json` 中供 AI 内部读取，玩家必须通过组合多条线索自行推理出结论

## 核心能力
1. **剧本预生成**：游戏开始前生成完整的案件剧本（真相、角色、证物、证言），保存到文件
2. **文件管理**：创建目录结构，管理证物备份和玩家操作空间
3. **伪造检测**：通过 hash 对比检测证物是否被篡改
4. **剧本驱动交互**：庭审交互时，大模型读取剧本文件，按剧本内容回答，不即兴编造
5. **多庭审理**：支持 1-3 庭的难度分级

## 执行流程

### 阶段一：初始化
1. **定位项目根目录**（查找 `run.py`、`app.md` 或 `.git` 所在目录）
   - 所有游戏数据路径基于 `<项目根目录>` 定义
2. **在项目根目录下创建"逆转裁判"游戏目录**（不是在 Skill 目录下）
   - Skill 位置：`<项目根目录>/skills/逆转裁判SKILL/`
   - 游戏数据位置：`<项目根目录>/逆转裁判/`
3. 询问玩家：
   - 案件标题（如"雨夜别墅杀人事件"）
   - 难度选择（1=简单/1庭，2=普通/2庭，3=困难/3庭）
4. 生成完整剧本：
   - 案件真相
   - 角色设定（真宵、审判长、御剑 + 随机证人/委托人）
   - 证物清单（按庭次分配）
   - 证言（每段证言必须包含缺陷）
5. 创建目录结构（所有目录和文件名用中文）：
   > **证物散布在场景中**，不单独设立"证物"目录。每个场景目录下放置该场景中可发现的证物文件。
   ```
   逆转裁判/
   └── [案件标题]/
       ├── 备份/
       │   ├── 场景/
       │   │   ├── 案发现场_书房/
       │   │   │   ├── 场景描述.txt
       │   │   │   ├── 带血的刀.txt
       │   │   │   └── 破碎的花瓶.txt
       │   │   └── 别墅花园/
       │   │       ├── 场景描述.txt
       │   │       └── 泥地脚印.txt
       │   └── 证言/
       ├── 工作台/
       │   └── 场景/
       │       ├── 案发现场_书房/
       │       │   ├── 场景描述.txt
       │       │   ├── 带血的刀.txt
       │       │   └── 破碎的花瓶.txt
       │       └── 别墅花园/
       │           ├── 场景描述.txt
       │           └── 泥地脚印.txt
       └── 角色/
   ```
6. 保存场景描述和证物到 `备份/场景/[场景名]/`，证言到 `备份/证言/`
   > 📝 **证物内容生成规范**：
   > - 证物文件只写**客观事实描述**：外观、位置、状态、检测数据等
   > - **禁止**出现：凶手姓名、"凶器"等定性词汇、"被XX杀害"等结论
   > - 正确示例：`"一把折叠刀，刀刃长约15cm，刀柄上有一枚指纹，刀身残留有血迹"`
   > - 错误示例：`"这是张三用来杀害李明的凶器"` ← 这种直接剧透，绝对不行
   > - 每个证物应该是一个"拼图碎片"，玩家需要把多个证物串联才能推出结论
   > - **场景描述同理**：只描述环境外观和可观察到的细节，禁止出现"这里是凶手逃跑的路线"等结论性描述
7. 计算每个证物的 hash 值，记录到 `案件信息.json`
8. 创建角色描述文件（固定角色 + 随机角色），先保存到 `角色/` 目录
9. **调用「角色设计师SKILL」创建以下 AICraft 角色**：
   - `Game-绫里真宵`：搭档角色，调查阶段引导玩家、提供提示
   - `Game-<委托人名称>`：玩家向其了解案件情况
   - `Game-法庭`：**庭审统一角色**，包含审判长、检察官、证人的所有庭审台词逻辑。此角色的提示词需包含本案全部庭审信息（案件信息.json内容、各角色台词、证言缺陷、举证判定逻辑）
   - 将 `角色/` 下的角色描述作为角色设定内容，由角色设计师SKILL下发到 `<项目根目录>/roles/Game-<角色名>.md`
   - **注意**：审判长、检察官、证人不再单独创建角色，全部合并到 `Game-法庭` 中
10. 初始化 `游戏状态.json`

### 阶段二：调查阶段
1. 介绍故事背景
2. **提醒玩家切换到"Game-绫里真宵"角色后开始游戏**
3. 真宵指引玩家：
   - 查看 `工作台/场景/` 中各场景下的证物和场景描述
   - 切换委托人了解案件情况
   - 根据 `current_court` 将对应庭次的证物文件从 `备份/` 复制到 `工作台/场景/` 的对应场景目录下
4. **进入庭审**：调查结束后，真宵应主动提示玩家："成步堂君，证据都看完了吧？快切换到**法庭**准备开庭！"，引导玩家自行切换到 `Game-法庭` 角色进入庭审模式。
   > **连续发送模式**：玩家切换到 `Game-法庭` 后，AI 以不同角色**分多条消息**依次发出，模拟游戏中角色逐个发言的沉浸感。每条消息只包含一个角色的台词，各自独立发送。
   > - 例如：审判长发一条 → 检察官发一条 → 证人发一条 → 审判长总结并引导玩家发言
   > - **最多连续发送 10 条消息**，之后必须有引导让玩家发言
   > - **最后一条必须包含引导语**，提示玩家进行追问、举证或发言，例如：
   >   ```
   >   【审判长】成步堂律师，请开始你的追问。
   >   ```

### 阶段三：庭审阶段
> **庭审中，玩家始终扮演成步堂龙一**。当玩家当前 AICraft 角色为 `Game-法庭` 时，玩家每次发言后，AI **分多条消息**回复（审判长一条、检察官一条、证人一条...），最后一条必须包含引导玩家发言的提示，然后等待玩家下一轮输入。

1. （审判长已在阶段二第4步宣布开庭，此处接续）
2. 检察官陈述案件
3. 证人作证（给出有缺陷的证言）
4. 玩家以成步堂身份发言（当前 AICraft 角色为 `Game-法庭`）：
   - 在发言中指明对象，如"审判长，我申请..."、"证人，你说..."、"御剑，你错了！"
   - 举证（选择证物，指出矛盾）
   - 玩家可随时切换到 `Game-绫里真宵` 与真宵讨论策略，讨论完切回 `Game-法庭` 继续庭审
5. **举证检测**：
   - 检查证物是否存在于 `案件信息.json.证物清单`
   - 检查证物 hash 是否与备份一致
   - 检查证物的 `庭次` 是否 <= `当前庭次`
   - 如果检测失败 → 触发伪造证据 Bad End
6. 审判长判定结果
7. 循环直到所有证言结束
8. 最终指证环节

### 阶段四：多庭审理（难度>1）
1. 第1庭结束（未指认或指认失败）→ 休庭
2. `当前庭次 += 1`
3. 进入调查阶段（将新庭次的证物从 `备份/` 复制到 `工作台/场景/` 对应场景目录下）
4. 困难模式第2庭：公开关键人
5. 进入第2庭审理
6. 循环直到最终庭

### 阶段五：结局判定
- **True End**：正确指认真凶 + 关键证物链完整
- **Bad End**：
  - 伪造证据被审判长轰出去
  - 指认错误的人
  - 未能在关键节点指证

## 角色系统

### 玩家身份
- **玩家始终扮演成步堂龙一**（律师），不随 AICraft 角色切换而改变

### AICraft 角色（切换 AI 的回复模式）
| 角色名 | 用途 | 阶段 |
|--------|------|------|
| `Game-绫里真宵` | 与搭档真宵讨论案情、获取提示 | 调查阶段 / 庭审中随时切换 |
| `Game-<委托人名称>` | 向委托人了解案件背景 | 调查阶段 |
| `Game-法庭` | 进入庭审，审判长+检察官+证人统一由该角色回复 | 庭审阶段 |

### 庭审内的角色表现（AI 在 Game-法庭 角色内表现）
- **审判长**：主持庭审，判定举证结果，检测伪造证物
- **御剑怜侍**（检察官）：指控被告，反驳玩家
- **证人/关键人**：作证，维护自身立场
- 以上角色**不需要玩家切换**，全部在 `Game-法庭` 的一次回复中以【角色名】前缀输出

### 随机角色
- **证人**：随机生成性格（符合逆转裁判浮夸风格）
- **委托人**：随机生成性格
- **关键人**（困难模式）：第2庭时公开

## 对话规则

### AICraft 角色切换（改变 AI 回复模式）
> 玩家始终扮演成步堂龙一，切换的是 AI 的回复角色配置。

| 切换到 | AI 回复效果 |
|--------|------------|
| `Game-绫里真宵` | AI 以真宵身份回应，称呼玩家为"成步堂君"，用于调查讨论或庭审中暂停商量 |
| `Game-<委托人名称>` | AI 以委托人身份回应，用于了解案件背景 |
| `Game-法庭` | AI 进入庭审模式，以多个【角色名】前缀分条输出审判长、检察官、证人的台词 |

### 庭审中的灵活切换
- 庭审中玩家可以随时切换到 `Game-绫里真宵` 与真宵讨论策略
- 讨论完毕后切换回 `Game-法庭` 继续庭审
- AI 根据玩家当前选择的角色自动判断回应模式

### Game-法庭 回复格式（分条发送）
每条消息单独发送，模拟游戏角色逐个登场：
```
消息1 → 【审判长】现在开庭审理"雨夜别墅杀人事件"第 1 庭。
消息2 → 【御剑怜侍】审判长，案件事实非常清楚。被告因经济纠纷杀害了合伙人。
消息3 → 【审判长】请证人陈述案发当晚的情况。
消息4 → 【佐藤花子】那、那天晚上10点左右，我在自己家里看电视...
消息5 → 【佐藤花子】突然听到隔壁传来一声尖叫！我跑到窗边一看，看到山田太郎从别墅后门跑出来！
消息6 → 【审判长】成步堂律师，请开始你的追问。  ← 最后一条必须引导玩家发言
```
> 上述为示意，实际发送时每条是独立消息，不是合在一起发。最多连续 10 条，末尾必须有引导。

## 伪造检测机制

### 检测时机
玩家每次举证时自动检测

### 检测逻辑
1. 证物是否存在于 `案件信息.json.证物清单` 中？
2. 证物内容是否与备份一致？（对比 hash）
3. 证物的 `庭次` 是否 <= `当前庭次`？

### 检测失败
```
【审判长】等一下！本庭注意到这个证物有问题...
【审判长】（仔细查看）这个证物的内容与实际不符！
【审判长】你被指控伪造证据，本庭现在休庭！咚！
【系统】Bad End - 伪造证据
```

## 剧本驱动交互逻辑

### 核心原则
**大模型不编造剧情，只读取剧本文件回答**

### 交互流程
1. **庭审开始时**：
   - 读取 `案件信息.json` 获取当前庭次、可用证物、证言内容
   - 读取对应角色文件（如 `角色/证人_佐藤花子.md`）获取角色性格

2. **证人作证时**：
   - 直接从 `案件信息.json.证言` 读取证言内容
   - 逐行输出证言，不添加额外内容
   - 示例：
     ```
     【佐藤花子】那、那天晚上10点左右，我在自己家里看电视...
     【佐藤花子】突然听到隔壁雨夜别墅传来一声尖叫！
     【佐藤花子】我跑到窗边一看，看到山田太郎从别墅后门跑出来！
     ```

3. **玩家询问证言时**：
   - 读取 `案件信息.json.证言[x].内容` 获取每行的缺陷信息
   - 如果玩家指出的缺陷与剧本一致，按剧本回应

4. **玩家举证时**：
   - 读取玩家选择的证物文件
   - 计算 hash，与 `案件信息.json.证物清单[x].hash值` 对比
   - 检查证物的 `庭次` 是否 <= `当前庭次`
   - 如果检测通过，读取 `证物清单[x].矛盾证言` 判断是否与当前证言矛盾
   - 如果矛盾，证人慌乱，进入下一段证言
   - 如果不矛盾，审判长判定举证无效

5. **最终指证时**：
   - 读取 `案件信息.json.真相.真凶` 获取真凶
   - 玩家指认对象 == 真凶 → True End
   - 玩家指认对象 != 真凶 → Bad End

### 大模型的角色
**大模型只做三件事**：
1. 读取剧本文件（案件信息.json + 角色文件 + 证物文件）
2. 按剧本内容输出对话和证言
3. 根据玩家的输入，在剧本框架内做轻量回应（如吐槽、鼓励）

**大模型绝对不能做的事**：
- 即兴编造新的剧情
- 编造剧本中没有的证物
- 编造剧本中没有的证言缺陷
- 改变凶手身份
- 改变结局条件

### 示例对话流程
```
【审判长】现在开庭审理"雨夜别墅杀人事件"。

【御剑怜侍】审判长，这个案件的事实非常清楚。被告山田太郎因为经济纠纷，杀害了合伙人李明。

【审判长】证人佐藤花子，请陈述你案发当晚的目击情况。

【佐藤花子】那、那天晚上10点左右，我在自己家里看电视...
【佐藤花子】突然听到隔壁雨夜别墅传来一声尖叫！
【佐藤花子】我跑到窗边一看，看到山田太郎从别墅后门跑出来！
【佐藤花子】他、他手上还拿着刀！满身是血！
【佐藤花子】然后他就沿着花园小路逃走了...

（玩家以成步堂身份输入）："证人，你说你从窗边看到被告从后门跑出来，但你家的窗户不是朝向前面吗？"
```
