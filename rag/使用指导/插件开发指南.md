# AICraft 插件开发指南

## 概述

AICraft 的能力扩展有三条路径：**Skill**（提示词模块）、**MCP**（工具调用模块）、**RAG**（知识库模块）。三者互补：

| 类型 | 本质 | 能做什么 | 不能做什么 |
|------|------|---------|-----------|
| Skill | 纯文本 prompt | 改变 AI 的回答风格和专业度 | 执行任何实际操作 |
| MCP | 外部工具服务 | 读写文件、调 API、跑代码 | 影响 AI 的说话风格 |
| RAG | 文档知识库 | 提供领域知识辅助回答 | 执行操作或改变风格 |

---

## 一、开发 Skill

### 什么是 Skill

Skill 是一个包含 `SKILL.md` 文件的文件夹。AICraft 扫描 Skill 目录，将已启用 Skill 的**名称和简短描述**注入到 System Prompt 中，引导 AI 按特定方式回答。

> **关键机制**：`build_skill_prompt()` 只提取每个 Skill 的名称 + 第一段非标题行（前 100 字符）拼接到 System Prompt。完整的 `SKILL.md` 内容**不会**发给 AI。这是为了防止模型在回复中念出技能描述。

**Skill 不执行代码，只是告诉 AI "你具备这个能力/按这个风格回答"。**

### 目录结构

```
skills/
├── toggles.json          # 开关状态（自动生成）
├── 翻译助手/
│   └── SKILL.md          # 必须存在
├── 代码审查/
│   └── SKILL.md
└── 自定义技能/
    └── SKILL.md
```

### SKILL.md 格式

```markdown
# 技能名称

一句话描述这个技能做什么（这行会被提取为 Skill 描述，显示在界面上，并注入给 AI）。

## 规则
- 具体规则1
- 具体规则2

## 输出格式
- 格式要求1
- 格式要求2
```

**要点**：

- **第一段非标题行**是关键——它会被提取为 Skill 的简短描述，这是 AI 唯一能看到的 Skill 信息
- 内容越具体越好，模糊的指令 AI 执行效果差
- 不要写"你是一个XX助手"这种废话，直接写规则和输出要求
- 详细规则可以写得非常具体（作为 SKILL.md 的参考文档），但要确保**第一段描述能准确传达核心能力**

### 示例：代码审查 Skill

```markdown
# 代码审查

你是一位严格的代码审查员，从安全、性能、可维护三个维度审查代码。审查后按严重程度分级输出。

## 审查维度

### 安全（Security）
- SQL注入、XSS、命令注入等注入风险
- 敏感信息硬编码（密钥、密码、Token）
- 不安全的反序列化、文件操作

### 性能（Performance）
- O(n²)及以上复杂度可优化的地方
- 不必要的重复计算、重复查询
- 内存泄漏风险

### 可维护（Maintainability）
- 函数/方法过长（>50行）
- 嵌套过深（>3层）
- 魔法数字/字符串未提取常量

## 输出格式
按严重程度分级：
- 🔴 严重：必须修复
- 🟡 建议：推荐修复
- 🔵 参考：可选优化

每条包含：位置 → 问题描述 → 修复建议
```

### Skill 注入机制

AICraft 的 `skill_loader.py` 工作流程：

1. 扫描 Skill 目录下所有含 `SKILL.md` 的子目录
2. 用 `_extract_description()` 提取每个 Skill 的**第一段非标题非空行**（最多 100 字符）
3. `build_skill_prompt()` 将已启用 Skill 的名称 + 描述拼接为：
   ```
   # 可用技能
   你具备以下技能，当用户问题匹配时可以调用对应工具：
   - 代码审查：你是一位严格的代码审查员...
   - 翻译助手：将用户输入的文本翻译为目标语言...
   ```
4. 这段文本被注入到 System Prompt 中

### 开发建议

- **一个 Skill 做一件事**，不要把翻译和写作塞同一个 Skill
- **描述要精准**，"翻译助手：将文本翻译为目标语言，支持中英日韩等常见语种" 比 "语言专家" 好 10 倍
- **命名用中文**，文件夹名即为用户看到的名称
- **调试方法**：在对话中明确说"请用 XX 技能回答"，看 AI 是否按预期风格输出
- **不生效怎么办**：检查描述是否精准——AI 只能看到名称和第一段描述，它不会知道 SKILL.md 里写了什么详细规则

## 二、接入 MCP

### 什么是 MCP

MCP（Model Context Protocol）让 AI 能调用外部工具。AICraft 通过 stdio 或 SSE 协议连接 MCP 服务器，将工具列表暴露给 AI 的 function calling。

### 两种连接模式

| 模式 | 说明 | 连接方式 | 适用场景 |
|------|------|---------|---------|
| **stdio** | 启动子进程，通过标准输入输出通信 | 长连接（后台 task 持有） | 本地命令行工具 |
| **SSE** | 连接 HTTP 服务器，通过 Server-Sent Events 通信 | 短连接（每次调用重建） | 远程服务 |

### 添加 MCP 连接

1. 点击「MCP」标签
2. 点击「添加连接」
3. 填写：
   - **名称**：连接显示名
   - **类型**：stdio 或 SSE
   - **stdio 模式**：填写 command 和 args（如 `python my_server.py`）
   - **SSE 模式**：填写完整 URL（如 `http://localhost:3001/sse`）
4. 点击添加，然后连接

### 使用官方 MCP 服务器

官方 MCP 服务器需要 Node.js 环境：

```bash
# 文件系统读写
npx @modelcontextprotocol/server-filesystem /path/to/workspace

# Python 代码执行
npx @modelcontextprotocol/server-python

# GitHub 操作
npx @modelcontextprotocol/server-github
```

添加时配置：
- 类型：stdio
- command：`npx`
- args：对应包名和参数（空格分隔），如 `-y @modelcontextprotocol/server-filesystem workspace`

### 自建 MCP Server（stdio）

以下是一个完整的 Python MCP 服务器示例，支持 `initialize`、`notifications/initialized`、`tools/list`、`tools/call` 等标准 JSON-RPC 方法：

```python
# my_tool_mcp.py
import json
import sys


def handle_request(request):
    """处理 MCP JSON-RPC 请求"""
    method = request.get("method", "")
    req_id = request.get("id")

    # ── 初始化 ──
    if method == "initialize":
        return {
            "jsonrpc": "2.0",
            "id": req_id,
            "result": {
                "protocolVersion": "2024-11-05",
                "capabilities": {"tools": {}},
                "serverInfo": {"name": "my-tool", "version": "1.0.0"},
            },
        }

    # ── 工具列表 ──
    if method == "tools/list":
        return {
            "jsonrpc": "2.0",
            "id": req_id,
            "result": {
                "tools": [
                    {
                        "name": "my_function",
                        "description": "我的自定义工具——执行某个具体操作",
                        "inputSchema": {
                            "type": "object",
                            "properties": {
                                "input": {
                                    "type": "string",
                                    "description": "输入参数说明",
                                },
                            },
                            "required": ["input"],
                        },
                    }
                ]
            },
        }

    # ── 工具调用 ──
    if method == "tools/call":
        params = request.get("params", {})
        tool_name = params.get("name", "")
        arguments = params.get("arguments", {})

        if tool_name == "my_function":
            result = do_something(arguments.get("input", ""))
            return {
                "jsonrpc": "2.0",
                "id": req_id,
                "result": {
                    "content": [{"type": "text", "text": result}],
                },
            }

    # ── 未知方法 ──
    return {
        "jsonrpc": "2.0",
        "id": req_id,
        "error": {"code": -32601, "message": f"Method not found: {method}"},
    }


def do_something(input_text):
    """你的工具逻辑"""
    return f"处理结果: {input_text}"


# MCP stdio 协议：逐行读取 JSON-RPC，逐行写入 JSON-RPC
def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        try:
            request = json.loads(line)
            # notifications/initialized 不需要回复
            if request.get("method") == "notifications/initialized":
                continue
            response = handle_request(request)
            print(json.dumps(response, ensure_ascii=False), flush=True)
        except Exception as e:
            error_response = {
                "jsonrpc": "2.0",
                "id": request.get("id") if "request" in dir() else None,
                "error": {"code": -32603, "message": str(e)},
            }
            print(json.dumps(error_response, ensure_ascii=False), flush=True)


if __name__ == "__main__":
    main()
```

添加到 AICraft：
- 类型：stdio
- command：`python`
- args：`my_tool_mcp.py`

### 自建 MCP Server（SSE）

SSE 模式的 MCP 服务器是一个 HTTP 服务。以下使用 FastAPI + `mcp` SDK 的示例：

```python
# sse_server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-remote-tool")


@mcp.tool()
def my_function(input: str) -> str:
    """我的自定义工具——执行某个具体操作"""
    return f"处理结果: {input}"


if __name__ == "__main__":
    mcp.run(transport="sse", host="0.0.0.0", port=3001)
```

添加到 AICraft：
- 类型：SSE
- URL：`http://localhost:3001/sse`

### MCP 工具调用流程

```
1. AICraft 连接 MCP 服务器，获取工具列表
2. 工具列表转换为 OpenAI/Anthropic function calling 格式
3. 注入 AI 请求的 tools 参数
4. AI 判断需要调用工具时，生成工具调用请求
5. AICraft 转发请求到 MCP 服务器（经过权限守卫检查）
6. MCP 服务器执行并返回结果
7. AI 收到结果后继续回答或再次调用工具
```

### MCP 权限守卫集成

AICraft 的权限系统（`permission_guard.py`）会在工具执行前拦截检查。对于自定义 MCP 工具：

- **文件操作类工具**：如果你定义了读写文件的工具，需要在消息中明确路径。路径会被检查是否匹配信任/拒绝策略
- **代码执行类工具**：如果工具名包含 `execute_python` 或 `execute_shell`，会被当作高风险操作，始终要求用户确认
- **自动授权**：在 MCP 连接卡片上开启「自动授权」可跳过所有权限检查

如果你希望自定义工具被权限守卫识别和管理，可以在 `permission_guard.py` 中为对应工具名添加路径参数映射（`TOOL_PATH_ARGS`）。

### 安全建议

- 限制文件访问范围，使用相对路径或限定工作目录
- 代码执行 MCP 应考虑沙箱隔离（AICraft 内置的代码执行器通过 `--run-script` 子进程运行）
- 不要在 MCP 环境变量中硬编码密钥
- 不信任的 MCP 连接保持「自动授权」关闭状态
- 生产环境 SSE 服务器应启用认证

## 三、配置 RAG 知识库

### 什么是 RAG

RAG（检索增强生成）让 AI 基于你的私有文档回答问题。AICraft 使用 ChromaDB 做向量存储，支持本地 ONNX 和远程 API 两种 Embedding 模式。

### 添加知识库

1. 准备文档目录，放入支持的文件（txt/md/py/json/csv/html/xml/docx/pdf）
2. 在 RAG 页面点击「添加数据源」，指定名称和目录路径
3. 配置 Embedding 模式（auto / api / local）
4. 点击「索引」建立向量索引
5. 对话时开启 RAG检索 开关

### Embedding 配置

| 模式 | 实现 | 维度 | 需要 |
|------|------|------|------|
| **auto** | 有 API Key 走硅基流动 API，否则走本地 ONNX | 384~1024 | 推荐 |
| **api** | 硅基流动 API（`BAAI/bge-large-zh-v1.5`） | 1024 | 免费 API Key |
| **local** | 本地 ONNX（`all-MiniLM-L6-v2`） | 384 | 首次下载 ~80MB |

> 模式切换后必须重新索引，因为不同模式的向量维度不兼容。

### 索引机制

- 使用 ChromaDB 持久化存储（`chroma_db/` 目录）
- `RecursiveCharacterTextSplitter` 分块：`chunk_size=500`，`chunk_overlap=50`
- 默认相似度算法：cosine
- 首次索引 local 模式时需下载 ONNX 模型
- 每次点击「索引」全量重建

### 自定义 Embedding

如需使用自定义 Embedding 模型或 API，修改 `rag_engine.py` 中的 `_get_embed_fn()` 方法，或通过 `config/rag_config.json` 配置：

```json
{
  "embedding_mode": "api",
  "embedding_api_key": "sk-...",
  "embedding_model": "BAAI/bge-large-zh-v1.5",
  "embedding_api_base": "https://api.siliconflow.cn/v1"
}
```

`embedding_mode` 支持三种值：
- `"auto"` — 自动选择
- `"api"` — 强制通过 `embedding_api_base` 调用 API
- `"local"` — 强制本地 ONNX

### 知识库最佳实践

- **文档要结构化**：用标题、列表、表格组织内容
- **一份文档一个主题**：不要把无关内容混在一起
- **关键信息前置**：重要结论放在文档开头（向量检索对开头内容更敏感）
- **定期重建索引**：文档更新后需要点击「重新索引」
- **文件名有意义**：文件名会被纳入检索范围
- **API 模式质量更高**：1024 维向量比本地 384 维检索精度更高

### 适合做 RAG 的内容

- 项目文档和 API 手册
- 公司内部知识库
- 技术规范和标准
- 产品使用说明
- FAQ 常见问题集

### 不适合做 RAG 的内容

- 超大文件（>10MB）：索引慢，检索噪声多
- 图片/视频：不支持（ChromaDB 无法处理非文本）
- 频繁变更的临时数据：需要频繁重建索引
- 扫描版 PDF（纯图片）：无法提取文本，需 OCR 预处理
